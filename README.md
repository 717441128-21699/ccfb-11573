# 门店点位采集系统(纯本地模拟)

商业选址用的连锁品牌门店点位采集系统。**全部本地模拟, 不调用任何真实地图平台**:
模拟接口内置 10 万点位真值(商圈扎堆 + 郊区空旷), 采集端按网格四分把点位拿全,
采完与真值比对 —— 漏采率 0、重复率 0。

## 快速开始

```powershell
py run_demo.py --fresh      # 完整流程: 生成真值→采集→验证→演化→重采→变化追踪
py run_demo.py --serve      # 跑完后启动后台 http://127.0.0.1:8000
py -m tests.test_core       # 单元测试 + 小规模端到端
```

`run_demo.py` 一次跑完七件事:

1. 生成 10 万点位真值(WGS84), 落盘 `data/truth_epoch1.json`;
2. 启动模拟地图接口(`:8123`), 行为对齐真实平台:
   单次最多返回 **200 条**、坐标 **GCJ-02 加偏**、随机 **超时/500/假空**;
3. 首轮采集: 按行政区多边形切初始网格, 超限格子四分下钻, 断点可续采;
4. 与真值比对, 输出漏采率/重复率;
5. 模拟"一个月后": 平台数据演化(400 关门 / 600 新开 / 250 搬家);
6. 重采并做变化追踪, 分别标出 新开/关门/搬家;
7. 覆盖分析: 哪些格子切到最小深度仍超限。

## 设计要点(对应需求)

| 需求 | 实现 |
|---|---|
| 网格四分 | `engine.py`: 初始 4×4 按行政区多边形裁剪; `count>200` 且深度<8 就四分, 直到拿全 |
| 坐标纠偏 | `coords.py`: GCJ-02→WGS84 迭代求逆(误差<1m), 入库前统一转换 |
| 去重 | `dedup.py`: 规范化(全半角/标点)后 `md5(名称|地址)` 主键去重 + 同名 25m 空间兜底; 接口按余量外扩返回(模拟中心+半径搜索), 边缘点位必在相邻格重复出现, 正好被拦住 |
| 真空 vs 失败 | 超时/5xx → 指数退避重试, 耗尽标 `failed`; 空结果再确认 2 次才标 `done_empty` |
| 断点续采 | 网格状态全在 SQLite, 重跑只取 `pending/failed` 格子, 不从头来 |
| 变化追踪 | `changes.py`: `snapshot_pois` 记录每次快照成员; 同名 500m 内的"关门+新开"重归类为搬家 |
| 覆盖分析 | `coverage.py` + 后台地图页: 格子按状态着色, `overflow`(最小深度仍超限)单独列出 |

## 目录

```
poi_collector/
  coords.py      坐标系转换
  geo.py         多边形/矩形几何
  db.py          SQLite(项目/网格/点位/快照/变化)
  mock_data.py   真值生成与演化
  mock_server.py 模拟地图搜索接口(故障注入)
  dedup.py       规范化与去重
  engine.py      采集引擎
  changes.py     变化追踪
  coverage.py    覆盖分析
  verify.py      真值比对
  webapp.py      后台(总览/覆盖地图/点位库/变化追踪)
run_demo.py      端到端演示
tests/test_core.py
```

## 后台

`py run_demo.py --serve` 或 `py -m poi_collector.webapp --db data/collector.db --port 8000`:

- **项目总览**: 点位数、网格状态、请求/重试/去重统计、漏采率/重复率、超限格子清单
- **网格覆盖地图**: canvas 绘制行政区 + 网格(采完绿 / 真空灰 / 超限橙 / 失败红)+ 点位 + 变化图层
- **点位库**: 名称/地址搜索
- **变化追踪**: 新开/关门/搬家明细

## 接真实平台时要改的地方

只有两处: `engine._query` 换成真实接口(加分页/签名/限流),
`coords.py` 按平台实际坐标系选择纠偏函数。网格、去重、续采、变化追踪逻辑原样复用。
